Что настроить в панели Remnawave, чтобы подписка открывалась в Clod Clash. Пользователю здесь делать
ничего не нужно.

## Правило ответа для клиента

Приложение представляется панели как `ClodClash/<версия> (Android)`. Без своего правила
панель отдаст ответ по умолчанию, а не конфиг mihomo, и подписка не добавится.

В **Subscription response rules** добавьте правило: регулярное выражение `^clodclash`
(регистр не важен), формат ответа **MIHOMO**. Это же правило обслуживает и десктопную версию.

Чтобы под именем сервера показывалось его **Server description**, в том же правиле
добавьте `^ClodClash/` в `responseModifications.additionalExtendedClientsRegex` — именно
префиксом, иначе правило отвалится при обновлении приложения.

```json
{
  "name": "Mihomo Clients",
  "description": "Response with generated YAML config (Mihomo Template)",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    {
      "headerName": "user-agent",
      "operator": "REGEX",
      "value": "^(?:FlClash|FlClashX|Flowvy|[Cc]lash-[Vv]erge|[Kk]oala-[Cc]lash|[Cc]lash-?[Mm]eta|[Mm]urge|[Cc]lashX [Mm]eta|[Mm]ihomo|[Cc]lash-nyanpasu|clash.meta|prizrak-box|[Cc]lod[Cc]lash)",
      "caseSensitive": false
    }
  ],
  "responseType": "MIHOMO",
  "responseModifications": {
    "additionalExtendedClientsRegex": [
      "^ClodClash/"
    ]
  }
}
```

<Callout title="Как проверить">
Запросите ссылку подписки с заголовком `User-Agent: ClodClash/0.0.1 (Android)`: должен прийти
YAML mihomo, а у узлов — поле `serverDescription`.
</Callout>

Шаблон MIHOMO и ключи, которые клиент перезаписывает, — в
[руководстве по настройке панели](https://github.com/Mrvibecodic/clod-clash/blob/main/docs/REMNAWAVE.md).
Заголовки ответа — на страницах [Заголовки подписки](/ru/docs/provider/headers) и
[Заголовки clod-*](/ru/docs/provider/clod-headers).

## Защищённое соединение

При добавлении подписки приложение само сначала пробует защищённый канал прослойки
[remnawave-subscription-middleware](https://github.com/Mrvibecodic/remnawave-subscription-middleware);
если канала у провайдера нет, подписка загружается обычным HTTPS-запросом. Пользователь
может выключить канал в свойствах подписки и включить снова.

Без прослойки на запрос канала (путь `/c1/…` на домене подписки) отвечает ваш сервер, и от
этого ответа зависит, добавится ли подписка:

| Ответ на незнакомый путь | Что делает приложение |
| --- | --- |
| 404 или 410 | сразу загружает подписку обычным путём |
| другой код 4xx | пробует канал ещё дважды; если так ответили все три попытки — обычный путь |
| соединение закрыто без ответа (например, nginx `return 444`) | так же, как другой код 4xx |
| 5xx (например, 502 от обратного прокси) | считает это сбоем по дороге: после трёх попыток подписка не добавляется |

Проверьте, что отдаёт домен подписки на любой незнакомый путь — это должен быть не 5xx:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://sub.example.com/c1/test
```

`404` — подходит. `000` с ошибкой `Empty reply from server` — соединение закрыто без ответа,
тоже подходит. `502` и другие 5xx — поправьте обратный прокси, чтобы на незнакомые пути он
отвечал 404.

Подписка с каналом после планового обновления (если обновления реже раза в 6 часов или выключены — и между
ними, не чаще раза в 6 часов) шлёт отчёт о качестве узлов: пинги и итоги 16–20 по узлам,
трафик, вид сети и внешний адрес, с которого делались замеры. Принимает и показывает отчёты
прослойка (вкладка Clod Clash → «Статистика»), если в ней включён приём. Замеры клиент копит,
только когда прослойка подтвердила приём в ответе подписки по каналу (так делают
свежие версии прослойки); нет подтверждения в очередном ответе — перестаёт копить
и стирает накопленное. Адрес замеров Android
узнаёт у Яндекса мимо туннеля сам; на ПК для этого нужны правила `DIRECT` в шаблоне — см.
[руководство по настройке
панели](https://github.com/Mrvibecodic/clod-clash/blob/main/docs/REMNAWAVE.md).

Внешний адрес и идентификатор устройства, связанные с подпиской, могут быть персональными
данными по 152-ФЗ и GDPR, и их оператор — провайдер, а не авторы клиента. Включая приём отчётов
или проверку 16–20, опишите это в своей политике конфиденциальности (цели, основание, сроки
хранения, получатели) и известите пользователей. Что именно отправляет клиент — в
[политике конфиденциальности клиента](https://github.com/Mrvibecodic/clod-clash-android/blob/main/PRIVACY_POLICY.ru.md).
