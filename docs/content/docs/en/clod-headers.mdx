---
title: "clod-* headers"
description: "Clod Clash's own headers that Android understands: values and what each one does"
---

Only Clod Clash understands `clod-*`. The panel does not send them by itself — add them in the
subscription settings under `customResponseHeaders`. Each one works only within its own
subscription.

## All headers

| Header | Value | What it does |
| --- | --- | --- |
| `clod-portal-url` | `https://` link | "Customer portal" button — where the plan is renewed |
| `clod-bot-url` | `https://`, `tg:` or `mailto:` link | "Bot" button |
| `clod-monitor-url` | `https://` link | "Server status" button |
| `clod-guide-url` | `https://` link | "Setup guide" button |
| `clod-announce` | text | permanent announcement; wins over `announce` |
| `clod-promo` | text | promo banner that can be closed |
| `clod-promo-url` | `https://` link | where a tap on the promo leads |
| `clod-lock-mode` | `true`, `lock` or `false` | locks the routing mode to `mode` from the template |
| `clod-ping` | `A/B` in ms, for example `150/300` | latency colour bounds. Without the header — `200/400` |
| `clod-disable-ping` | `true` only | a check mark or cross instead of milliseconds |
| `clod-show-0hosts` | `true` or `false` | show the panel's placeholder nodes as they are |
| `clod-mobile-only` | server names separated by `\|` | servers for the mobile network only: off the SIM network they are not shown |
| `clod-16-20-check` | `true` only | the 16–20 check: whether traffic through a server is cut off on the user's network; "cut off" and "not responding" marks |
| `clod-new-sub` | a domain, for example `backup.example.com` | spare subscription address (domain) — in case the main one does not answer |
| `clod-move-sub` | `true` only, together with `clod-new-sub` | move everyone to the spare address |

Instead of `true` / `false` you can use `1` / `0`, `yes` / `no`, `on` / `off` — except for
`clod-disable-ping`, `clod-16-20-check` and `clod-move-sub`, which accept only `true`. A value that is not understood counts as no
header. Send non-ASCII text as `base64:<text in base64>`.

`clod-*` headers that work on desktop only are not listed here — Android does not understand them.

## Provider links

"Customer portal", "Support" (`support-url`), "Bot", "Server status" and "Setup guide" are
gathered in a block named after the subscription at the top of the **More** tab. Only the links
that were sent are shown; with none, there is no block. "Customer portal" and "Support" also
appear on the subscription card when expiry is near or has passed.

## Announcement and promo

- **`clod-announce`** — a permanent announcement on the home screen, shown while the panel
  sends it.
- **`clod-promo`** — a banner for offers under the announcement, collapsed to two lines. It can
  be closed with a cross; a new text brings it back, and without the header it disappears with
  the next update. **`clod-promo-url`** makes it clickable.
- Length — up to 300 visible characters.
- Words can be coloured: a `#RRGGBB` code right before a word, for example
  `#EF4444IMPORTANT: node under maintenance`. The colour lasts until the next space and does
  not count towards the length.

## Routing mode: `clod-lock-mode`

Locks the mode to the one in the template's `mode:` (without it — "Rule mode"). The mode row
says "set by your provider" and the mode cannot be changed.

| Value | What happens |
| --- | --- |
| `true` | the mode is locked while the panel confirms it. If the subscription has not updated successfully for more than 72 hours (or three update intervals, if longer), the lock lifts by itself; the next successful update brings it back |
| `lock` | the mode is locked with no expiry |
| `false` | no lock |

For compatibility with Prizrak-Box, `global-mode: false` is read as `clod-lock-mode: true` and
`global-mode: true` as "no lock". `clod-lock-mode` wins.

## Latency

- **`clod-ping: A/B`** — up to `A` ms latency is green, up to `B` yellow, red beyond. Two
  integers separated by `/`, `1 ≤ A < B ≤ 60000`, otherwise the header is skipped.
- **`clod-disable-ping: true`** — on the home screen and the Servers tab a check mark (the server
  answers), a cross (it did not) or a dash (not checked yet) instead of milliseconds.

## The 16–20 check: `clod-16-20-check`

With `true` the app checks every server of the subscription on the user's network itself: it
downloads 64 KB through the server and sees whether all of it arrives, whether it stops after the
first kilobytes ("cut off") or nothing gets through ("not responding"). The outcome is a mark next
to the latency in the Servers tab and on the home screen; tapping it opens an explanation with a
"Contact support" button (when `support-url` was sent). The app does nothing to the servers:
latency and selection stay as they were. New servers and servers whose connection data changed are
checked; "working" and "cut off" are rechecked every 3 days, "not responding" after 6 hours on the
same network. Results are kept per subscription and per network. Without the header (or with any
value other than `true`) there are no checks and no marks.

## Servers for the mobile network only: `clod-mobile-only`

The value is the exact server names separated by `|`, for example `Moscow LTE|MTS Saint Petersburg`.
Letter case matters; spaces around a name are ignored. A server whose name contains `|` cannot be
listed. The names apply to servers from the subscription and from its proxy providers alike, including
servers a provider adds on a later update.

- On the mobile network (the SIM network) these servers are shown as usual, marked "mobile network".
- On any other network — Wi-Fi (a hotspot from another phone too), cable, USB — they are in no
  group and not in the server list, cannot be selected and are not checked. A group whose selected
  server is one of them — or, with nothing selected, whose first server is — uses the first visible
  server, or else the first group that still has a visible server; never a direct connection. On the
  mobile network it returns to the selected server by itself.
- Servers that connect through such a server (`dialer-proxy`) are hidden together with it.
- If only such servers are left in a group, off the mobile network the group lets nothing through
  rather than sending traffic directly; the list shows "Servers available only on mobile network"
  instead of servers.
- A template rule that names such a server directly still goes through it — servers are hidden from
  groups only.

Send names with Cyrillic letters or flags as base64 of the whole value: `🇷🇺 Москва LTE|МТС Питер`
is `base64:8J+Ht/Cfh7og0JzQvtGB0LrQstCwIExURXzQnNCi0KEg0J/QuNGC0LXRgA==`.

## Placeholder nodes: `clod-show-0hosts`

Without the header the app recognises the panel's placeholder nodes (expired subscription, no
traffic left, "no servers") and shows its own screen with the reason instead. With `true` the
panel's nodes go into the server list as they are. The device limit screen does not depend on
this header.

## Spare address: `clod-new-sub` and `clod-move-sub`

- **`clod-new-sub`** — a domain only: `backup.example.com`, without `https://`, port, path, `?`
  or `#`. Anything else is skipped. The spare address is `https://`, this domain and the path
  with parameters of the main address: for `https://panel.example.com:8443/sub/abc` it is
  `https://backup.example.com/sub/abc` (the main address's port is not carried over).
- How to write the domain so the app accepts and recognises it:
  - an internationalised domain only in punycode: `xn--e1afmkfd.xn--p1ai`, not `пример.рф`;
  - no trailing dot: `backup.example.com`, not `backup.example.com.`;
  - letter case does not matter;
  - the spare server answers on port 443.
- Write the domain in the users' subscription links the same way — in punycode and without a
  trailing dot. Otherwise the app does not recognise the main address's domain in
  `clod-new-sub`, takes it for a spare one, and with `clod-move-sub` "moves" the subscription to
  the same server.
- The spare address is used only when the main one does not answer. The subscription from it is
  applied as a normal update. A device limit refusal is not retried on the spare address — it
  is the same panel.
- Every successful update decides again: the header came — the domain is remembered (a new one
  replaces the old one), it did not come — there is no spare address any more. The domain of the
  main address does nothing.
- **`clod-move-sub: true`** works only together with `clod-new-sub`. After an update with it the
  app checks the spare address. If it returns the subscription, the subscription address changes
  to the spare one for good and the user sees the notification "The provider updated the
  subscription address"; server choice, mode and subscription name stay. If it does not answer
  or refuses, nothing changes, and the next update with this header tries again. On the new
  address the same header does nothing.
