## Tunnel or local proxy

By default the app brings up a tunnel for the whole device. That is the **Route system traffic**
switch in **More → Network**.

<Shot src="en/network.png" alt="Network settings: the system traffic switch and VPN options" />

Turn it off and there is no tunnel: the core works as a local proxy, its address is shown under
the switch, usually `127.0.0.1:7890`. Only apps where this proxy is configured go through it.

<Callout title="Proxy port">
The port comes from the subscription. If it does not set one, 7890 is used — unless the
subscription sets its own HTTP port or enables `allow-lan` (then no port is opened for you,
otherwise it would be visible to the whole network without a password). Set your own in
**More → Core features → Override → Mixed port**: an empty field means "do not change",
`0` turns the proxy off.
</Callout>

The **Network** settings can only be changed while the tunnel is off (except "Drop connections
when the network changes").

## Routing modes

**More → Mode** (present once a subscription is added):

| Mode | What it does |
| --- | --- |
| **Rule mode** | The subscription's rules decide what goes through a server and what goes direct |
| **Global mode** | All traffic goes through the server chosen in the `GLOBAL` group |
| **Direct mode** | The tunnel is up, but traffic bypasses the servers |

The choice is remembered per subscription. By default the mode comes from the subscription.

In global mode only the `GLOBAL` group on the Servers tab matters. If nothing is selected there
or `DIRECT` is, the app picks the first suitable server; if there is none, traffic is blocked rather than sent
direct — the app will warn you.

<Callout type="warn" title="The provider can set the mode">
A provider can fix the mode for a subscription. The mode row then says "set by your provider"
and cannot be changed. A regular lock lifts by itself if the subscription has not updated for
more than three days (or three update intervals, if the interval is longer) and comes back with
the next successful update. There is also a lock without an expiry.
</Callout>

## Network stack

**More → Network → Stack mode** — how traffic is captured: "Auto",
"System stack", "gVisor stack", "Mixed stack" or "MIPS stack". The default is "Auto": the stack from the subscription,
or MIPS if it sets none. The **Stack in use** row shows what is running now. Change it only if
your provider asks you to.
